## Polaris v1.0.13

### 修「文件夹下载 / 多文件下载失败」

反馈原话：「文件夹下载，多文件下载失败」。逐条查下来，这条链路有 5 个会直接坑到真实服务器（尤其 JumpServer/KoKo、H3C 这类设备的 SFTP）的点，全部修掉：

| # | 原来的问题 | 现在的行为 |
|---|---|---|
| 1 | 目录里**任何一个子目录列不出来**（root 拥有的子目录、设备限制），`walkRemote` 直接抛错 → 整批不下载，只弹「下载失败: Permission denied」 | 该子目录只记一条失败项（带原因，传输列表出「✗ 失败」行），同目录其它文件照常下完 |
| 2 | 批量并发 2 路在「SFTP 串行处理」的设备上会让部分文件失败（**单文件能下、全选就挂**） | 失败文件在批量结束后**逐个串行重试一次**（重试前重开 SFTP 通道），成功并入结果（界面 ✓，日志「下载重试成功」） |
| 3 | 符号链接指向目录时被当文件下载（`readdir` 报的是链接自身 mode `0o12xxxx`） | 按 `stat`（跟随链接）判真实类型：链接到目录继续递归，链接到文件按文件下；`visited` 防止链接成环 |
| 4 | 目录被误传 `isDir:false`（列表缓存/旧状态）→ 把目录当文件读，必然失败 | `sftp:downloadMany` 对每个条目 stat 兜底，是目录仍按目录递归 |
| 5 | 批量进度 `total` 被回调参数遮蔽 → 多文件下载的总进度条恒 100%（看着像"瞬间完成"） | `total` = 全批总字节，进度条按真实百分比走 |

顺带修：

- **失败原因像人话**：本地写失败时按错误码补提示——路径过长（Windows 260 字符限制）、磁盘空间不足、同名位置已经是文件夹、文件被占用 / 只读 / 杀软扫描。
- **空文件夹不再消失**：递归时先把本地子目录建出来，勾选带空目录的文件夹也会完整落地。

回归用例 `verify-sftp-download-many.js`（16 条）：嵌套 4 层 / 中文 / 空格 / `#` / 空文件 / 空目录整体下载、软链→目录递归、软链→文件、无权限子目录隔离、首次读失败串行重试、进度 `total` 正确、`isDir:false` 兜底、空目录判成功、界面失败行、重试日志。修复前 5/11 红；另外 `verify-sftp-download-fail` 7/7、`verify-sftp-cancel` 9/9、`verify-sftp-stress` 7/7、`verify-batch-sftp` 5/5、`run-verify --pure` 12/12 脚本 103 断言全绿。
