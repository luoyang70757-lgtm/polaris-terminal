# Polaris v1.0.10（2026-11-06）

本版修一个**会把命令吞掉**的输入法问题:中文输入法卡在"假组合"状态后,敲的字符**到不了终端**,只有退格和回车还有反应。

## 你遇到过的样子

- 终端里怎么打字都没反应,屏幕上也不显示,像是键盘失灵;
- 敲退格能删字、回车能换行 —— 说明连接是好的,是**输入被吞了**;
- 日志里能看到 `KEY 'Process' - kc=229`,但**没有任何数据送到远端**。

## 原因

输入法(IME)被系统/ Chromium 卡在"正在组合"的假状态:每个按键都被输入法拦走当成"组合中",终端一个字符都收不到。终端里本来有自救逻辑 —— 连续出现 **3 个**死键就重建输入法会话 —— 但实际打字节奏是「连按两下 → 敲退格 → 再连按两下」,**中间那下退格把计数清零了**,所以永远触发不到阈值,只能一直吞。

## 现在怎么做

1. 每个 `Process/229` 先**等 150ms** 再判定:这 150ms 里只要来了真正的组合事件(`compositionstart`),就说明是正常拼音输入,不打扰你;
2. 等不到组合事件 ⇒ 确认是死键,**3 秒内累计 2 个**就重建输入法会话(`blur()+focus()`,让 Chromium 重新向系统申请 IME 会话);
3. 重建时状态栏提示一次「输入法一直处于激活状态,字符键被吞了:请切到英文输入法再输命令」——终端里输命令本来就该用英文输入法;
4. 两个死键相隔超过 3 秒不累计,不会因为你偶尔误触就把会话炸掉。

## 顺手修掉的隐患

旧实现里"打了个真字符就把死键计数清零"这段逻辑挂在 xterm 的 textarea 的 `keydown` 上,但 xterm 处理完普通按键会 `stopImmediatePropagation`,后注册的监听**根本收不到**(实测只有 `229` 能收到)。也就是说那个清零从来没生效过。现在改用 `term.onData`(真实字符必定触发,它就是送进 SSH 的那条路)。

## 回归

新增 `verify-ime-deadkey.js`(9 条断言,全绿;修复前 6/9):

- 单个死键**不**重建(不误伤正常输入法);
- 3 秒内 2 个死键 ⇒ 重建会话;
- 重建后状态栏给出输入法提示;
- 间隔 > 3 秒的两个死键不累计;
- 真实组合(拼音)期间不重建、不打断候选窗,组合结束后统计归零;
- 40ms 内的"2 连发"不漏计(每个死键各自结算);
- 重建后键盘仍可用、焦点回到终端。

其他回归:`run-verify.js --pure` 12/12 脚本 103 断言;`verify-bufferfocus` 4/4、`verify-line-clear` 6/6、`verify-autolock-input` 17/17、`verify-term-links` 28/28;`verify-space-composition-flush` 维持历史基线 4/6(与本次无关,见 `docs/verify-known-red.md`)。
