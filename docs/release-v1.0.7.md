# Polaris v1.0.7（2026-11-03）

本版是**收尾打磨**：堡垒机面板去掉重复选择控件，修掉「每次连接都弹信任框」的体验问题，同时把「全量回归」和 CI 测试补上。

## 修复：总是弹「信任并连接」

以前遇到「每台新主机都要点一次确认」，用户只能自己去设置里翻「自动信任新主机密钥」。现在：

- 首次连接的弹窗多了第三个选项 **「信任并记住所有主机」**——点一次立即生效，以后连任何新主机都不再问（仍会记录指纹并逐次校验，指纹变化照样断开）；
- **指纹没存下来会明确告诉你**：写盘失败（数据目录只读/被清理）时，状态栏红字提示 `XX 的指纹没能保存到 <路径> → 下次连接仍会询问`，不再只是反复弹窗；
- 指纹写入后**回读校验**，避免“明明点了信任、其实没存”的静默失败；
- 排查手册：`docs/host-trust.md`（为什么会反复问：`host:port` 不同 / 目录不可写 / 集群多把主机密钥）。

## 改进：堡垒机面板不再三重选控件

右侧面板以前有三个控件都在做同一件事（选一台堡垒机并加载）：顶部标签栏、地址栏下拉、地址输入框。
现在分工明确：

| 控件 | 职责 |
|---|---|
| 顶部标签栏 | 已保存堡垒机的**唯一入口**（切换 / × 关闭 / 右键编辑删除） |
| 下拉 | 只放标签栏覆盖不到的站点：**左侧 JumpServer 服务器**、**已有资产的堡垒机 URL**，按来源分组；没有任何额外站点时整个下拉自动收起 |
| 地址输入框 | 手输任意 Web 地址，「打开」或回车加载 |

配套细节：双击左侧资产进入时标签会同步高亮（内容与标签始终一致）；下拉选完自动复位，同一站点可以反复选。

## 改进：新手引导不再叠弹窗

首次使用引导原本会在约 40ms 后就弹；如果此时你正好打开了新建会话 / 导入 / 堡垒机配置，它会盖上来抢焦点。现在检测到已有弹窗就等待（最多等 ~7s），不叠。

## 工程：全量回归入口 + CI 测试

- **`node run-verify.js`**：串行执行全部 `verify-*.js` 并汇总「脚本 X/Y 通过 + 断言数 + 失败清单」，失败脚本会重跑一次并标记 `flaky`（吸收 CDP/mock 抖动）。
  - `--pure` 只跑纯 Node 断言（无需 Electron/显示环境）
  - `--e2e` 只跑 CDP 端到端
  - `--only=bastion` 按文件名过滤（可多次传）
  - `--list` 看计划、`--fail-fast`、`--timeout=N`、`--retry=N`
  - 取代旧的 `test-all.js`：后者含真实环境凭据被 `.gitignore` 排除，新克隆里根本不存在
- **CI 现在会跑测试**：新增 `.github/workflows/test.yml`（push / PR 触发，纯 Node 断言，秒级，不装 Electron 二进制）；发布流程仍是 tag `v*` → `build-windows.yml`。
- `npm ci` 支持 `POLARIS_SKIP_ELECTRON=1`，跳过 144MB Electron 下载（仅纯 Node/打包场景）。

## 已知红灯（与本版改动无关）

`docs/verify-known-red.md` 记录了 3 个稳定失败的旧用例（debug 面板 KEY 日志、空格组合残留看门狗、真实 vim 右键菜单），已用 `git stash` 回到改动前复核：**同样失败**，属历史漂移，留给单独一轮排查。全量跑时会显示为红灯，不会被静默跳过。
