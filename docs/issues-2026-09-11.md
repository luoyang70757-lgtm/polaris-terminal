## 1. 🔴 自动填充密码明文进会话日志/录制（已实测）

**症状**：开启「自动填充密码」后，`sudo`/`Password:` 提示处自动发送的密码，被**明文写进** `<数据目录>/session-logs/*.log`（以及开启录制时的 `.jsonl` 输入事件）。

**根因**：渲染层自动填充走 `window.api.sshWrite`（`renderer.js:10561`），而主进程 `ssh:write`（`main.js:1497-1501`）对**所有**输入做录制打点与会话日志落盘：
```js
const rec = recSessions.get(sessionId);
if (rec && data) recorder.writeInput(rec.file, ...);
writeSessionInput(sessionId, data);   // ← 密码也走这里
```
渲染层注释声称「密码只发送、绝不写入调试日志/命令记录」——该承诺只在**调试面板/命令记录**成立，主进程这条链路没有豁免。

**实测**（`verify-autofill-log-leak.js`，本机跑过）：
```
✓ 终端未回显密码
✓ 调试面板无密码明文
✗ 会话日志里出现密码明文 → leak_….log → …sudo[sudo] password for admin: admin123⏎…
```

**修法**（✅ 已于 2026-09-11 实施）：`ssh:write` 增加 `opts.noLog` 标记（自动填充传它），主进程据此跳过 `recorder.writeInput` 与 `writeSessionInput`；并加兜底 `isSecretInput()`——待写入文本包含该会话密码（长度 ≥3）时一律不记，覆盖未来新增调用方与用户手敲密码。登录宏按「不记」处理会丢审计，故仍照常记录（宏里若含密码，由兜底命中跳过敏感情形）。

**未覆盖**：Telnet 会话的密码不走 `ssh:write`（自动登录在 `lib/telnet-client.js` 内部发送，本就不入日志）；用户在 Telnet 提示符手敲的密码无 `connOpts.password` 可比对，兜底无法命中。

**验证**：扩展 `verify-autofill-log-leak.js`（已存在，含 ①②③ 三条断言）。

## 2. 🟠 取消传输 = 删半成品 + 不留续传点 + 文案误导

**症状**：手动取消一个大文件上传/下载后，远端（或本地）**半成品被删除**，下次只能全量重传；状态栏报「上传校验失败:远端 X B ≠ 本地 Y B」，而不是「已取消」。

**根因**：watchdog 命中取消时只销毁流、**不结算 promise**（`lib/ssh-client.js:288-291` / `364-368`）：
```js
if (shouldCancel && shouldCancel()) { cancelled = true; try { ws.destroy(); } catch {} return; }
```
随后 `ws.on('close')` 让 promise **resolve 成成功** → 进入校验分支 → stat 不符 → 读回核对 → `unlink` 远端残缺文件并抛「上传校验失败」。因为文件已删，`recordUploadPartial` / `recordDownloadPartial` 也记不下续传点（`cur > 0` / `existsSync` 不成立）。

**影响**：与项目主打的「断点续传」语义冲突——用户以为取消后可续，实际被清掉。

**修法**（需产品取舍）：取消时应 **reject 专用错误**（`code:'CANCELLED'`），保留半成品并记录中断点；由调用方 `sftpJobDone({cancelled:true})` 表达「已取消」，不再走校验/删除路径。UI 的「已取消」文案已正确（`sftpJobDone` 里 `cancelled: shouldCancel()`），只有底层要改。

**验证**：`verify-sftp-stress.js`（含续传决策表）+ 手动取消大文件后断言远端半成品仍在、续传点已记。

## 3. 🟠 批量上传/下载未合并到加固后的传输管线

`main.js:708-757` 的 `sftp:batchUpload` / `sftp:batchDownload` 用 `sftp.fastPut` / `fastGet`：**无进度事件、无 stat 对账、无读回核对、无断点续传、无取消**，是唯一没跟上 v1.0.35+ 加固的传输路径（单文件/目录路径已有节流进度 + 三态校验 + 续传 + 取消）。

**修法**：改为复用 `startUploadJob` / `startDownloadJob`（多主机循环 + 每台一个 jobId），或至少接 `sshClient.uploadFile/downloadFile`。

**验证**：新增/扩展批量相关 verify，断言进度事件到达且失败有明确错误。

## 4. 🟠 关闭「命令记录」后命令补全永久失效

`tab.inputDirty = false` 全项目**只有一处**（`renderer.js:7792`），且被夹在：
```js
if (lineOnEnter != null && state.settings.cmdRecord !== false) {   // :7789
  if (tab.inputDirty) { tab.inputDirty = false; ... }
```
关掉命令记录（设置项或面板「○ 已暂停」）后，用户按一次 ↑/↓ 调历史 → `inputDirty` 永为 true → `maybeShowCmdComplete`（`:2714`）永久早退 → **v1.0.38 的命令补全在该标签彻底不再弹**，提示符学习（`:7774`）同步停摆。

**修法**：把 dirty 复位移出 `cmdRecord` 判断（是否记录不影响「本地镜像是否可信」）。

**验证**：`verify-recommend.js` 相关 + 新增断言：关闭记录 → 按 ↑ → 再敲 2 字符仍弹候选。

## 5. 🟠 `flash:/` 设备根的路径拼接与面包屑

`renderer.js:8565` `sftpJoin` 只特判 `'/'`：
```js
return state.sftp.path === '/' ? `/${name}` : `${state.sftp.path}/${name}`;
```
→ 路径为 `flash:/` 时得到 **`flash://name`**（双斜杠）；`renderSftpPath`（`:8686`）把 `flash:/` 渲染成 `/flash:`（点它跳到不存在的路径）。v1.0.41 起 `sftpParent` 会返回 `flash:/`，这条路径**变得可达**。

**影响**：H3C Comware 设备上，退到设备根后进目录/上传/删除/全选的路径都错。

**修法**：`sftpJoin` 改为「结尾是 `/` 就不再补分隔符」；`renderSftpPath` 认 `x:/` 前缀为根段并据此累加。补 `sftpParent` 的用例（`flash:/` ⇒ `flash:/`、`flash:/a` ⇒ `flash:/`）。

**验证**：`verify-sftp-up.js`（已覆盖 sftpParent 用例，可加 sftpJoin/面包屑断言）。

## 10. 🟡 H3C/批量连接抢焦点（✅ 2026-09-11 已修）

**根因**：`connectToServer` 无条件 `activateTab` → `term.focus()`，而批量入口逐台调用（`batchBastionConnect` 每 500ms、`batchSavedAssetConnect`/`batchJmsConnect` 每 300ms）→ 正在看的终端被逐台切走、焦点被抢。

**修法**：`connectToServer(session, opts)` 支持 `opts.background`（后台开标签：不切激活标签、不抢键盘焦点；无激活标签时仍走前台，避免空态）。**5 个批量入口全部传入**：
`batchConnect`（会话列表批量）、`menuConnect`（菜单「连接选中会话」）、`batchJmsConnect`、`batchBastionConnect`、`batchSavedAssetConnect`（`opts` 沿 `jmsConnect`/`bastionConnect`/`handleAccessClientUrl`/`bastionConnectAsset` 一路透传）；批量时不再逐台刷状态栏（由批量入口统一提示）。

**连带修掉一个被掩盖的焦点 bug**：`renderLayout()` 会重建终端容器 DOM（把激活面板摘下再挂回），**挂回不恢复键盘焦点 → 焦点掉到 body**；旧版因为紧接着 `activateTab`(内含 `term.focus()`) 而被掩盖（按键靠 BODY 兜底转发仍能打，但 `activeElement` 不在终端上）。现在：
- `activateTab` 在 `renderLayout` **之后**把焦点补回激活终端（用户在搜索框/地址栏打字时不抢）；
- 后台模式在 `renderLayout` 后按"原本焦点是否在激活终端"还回焦点。

**已知取舍**：后台标签的 pane 不在 DOM 里，`fit` 量不到尺寸 → 该标签先按 **80x24** 建 PTY；用户点开时 `activateTab → fit + scheduleRefit → sshResize` **自愈**（测试实测 80 → 98 列）。

**回归**：`verify-batch-focus.js`（12/12）——① 会话列表批量：激活标签与焦点都不变、新标签照常连上；② **H3C 资产批量（用户报的场景，走 mock 真实登录+accessUrl）**：激活标签不被打断、焦点不被新终端抢走；③ 点开后台标签能激活并尺寸自愈；④ 对照：单台用户连接仍前台激活+聚焦（改动只作用于批量入口）。相邻回归：`verify-bodyfocus`（全绿）· `verify-bufferfocus` 4/4 · `verify-bastion-merge` 9/9 · `verify-h3c-native` 15/15。
